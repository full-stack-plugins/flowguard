# Immutable SpecGuard review consumed by FlowGuard

Status: local fixture implementation for independent review. No production issuer.

SpecGuard owns structural correctness and specification baseline comparison. Its completed REQUIRE_APPROVAL report remains immutable. Approval references do not turn the specialist's decision into ALLOW. FlowGuard creates its own technical gate result and composite obligation scopes after independent GE eligibility checks.

The existing SpecGuard RunHistory.attach_current API creates a borrowed view with approval references and a different envelope digest. Original history, contract, facts, report and domain bytes are unchanged. A producer record for the old digest cannot authenticate the new view. Approval purpose, action, binding, contract, expiration and revocation are checked on consumption. The fixture controller also re-authenticates the actual ApprovedBaseline through SG's fixture approval port at each SG producer consumption. No cached ValidatedBaseline grants future eligibility.

The original four-provider fixture has no specification source and cannot be relabelled as a five-provider candidate. A separate real repository first commits the baseline specification, parses that commit into an ApprovedBaseline, and then commits a text change plus the compact baseline record. All five native producers bind the same current candidate/base/task/namespace-qualified requirements. The committed baseline's exact bytes equal SG canonical baseline serialization; TG and FG therefore naturally freeze the same baseline digest. No native returned field is patched to fit.

Protected native expectations, contracts and source mappings precede all completed specialist results. SG source bytes are checked against immutable GG tree objects before source snapshot preparation. Original CodeGuard command, schema, raw stdout and aggregate exit 3 remain unchanged. Domain source digests and policy snapshots remain independently scoped.

Actual SG partial source-budget analysis, bound failure and cancellation cannot be repaired by approval. Attachments require completed complete REQUIRE_APPROVAL; FG rejects invalid/error input or reports BLOCK for incomplete required providers. A valid local fixture review permits only a new FlowGuard technical ALLOW under the explicitly configured fixture issuer. It does not grant merge, release, promotion or write permission.

Implementation lives in FG examples/tests/fixtures to avoid an SG→FG dependency cycle. The shared fixture supports subsequent readonly workflow-DAG contract testing; no stage success is prefilled.
