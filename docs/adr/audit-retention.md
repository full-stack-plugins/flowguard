# Local tenant audit and required-artifact retention

This profile composes the existing GE AuthorityProvider/AuditRecord with MemoryRunStore publication checks. It does not supply production authentication, a general controller/database, filesystem tenant isolation, or execution grants. The protected controller chooses TenantPolicy (tenant/repository/consumer and reader allowlists), implements CallerPort from its actual authenticated session, supplies protected time, and selects explicit retention durations. Candidate code/configuration must not control these inputs. A Rust trait is not a security sandbox; a dishonest trusted caller can fabricate identity mappings.

LocalAuditStore owns a completed GateRun by move, after checking its actual MemoryRunStore publication. The run retains native contract/facts/report bytes and retained upstream evidence; no caller-passed green flag substitutes for them. Observing required-artifact expiry during consumption or an authorized remove drops those owned bytes. artifact_seconds is an availability deadline; there is no background deletion timer or claim of physical erasure at that instant. An in-flight Arc may keep them alive until its call returns, but a post-callback availability check prevents eligibility after removal. Run IDs cannot be reenrolled after removal/expiry. Original MemoryRunStore envelope history remains unchanged.

Consumption checks the current caller's tenant/role/validity, retained artifact lifetime, exact current publication and fresh GE producer/approval authority. It refreshes caller identity again and rechecks publication/availability after callbacks. Neither store mutex is held while external identity/authority ports run. The result is an observation at consumption, not an atomic authorization to perform a later write. Required audit capacity failure also refuses success. Unauthorized requests return Access regardless of run existence or audit capacity; recording that already-denied access is best effort under the fixed bound.

Storage is explicitly process-local trusted-controller memory; no default audit files or source writes are introduced. Logical input accounting bounds retained gate/evidence/policy bytes to 64MiB in aggregate; bookkeeping is separately bounded to 1024 runs and at most the configured 1..1024 audit entries. Aggregate retained input size is streamed over borrowed values before ownership registration, without constructing a second serialized artifact copy. Capacity exhaustion closes consumption and never deletes immutable history to make room. A production deployment must separately select authorized durable storage, tenant isolation and failure recovery; MemoryRunStore behavior is not durable parity.

Audit entries append fixed operation/outcome enums, monotonically numbered sequence, protected timestamp and digests of tenant/caller/run, plus GE's minimized audit record when available. They contain no raw credentials, caller/approval references, identity strings, producer diagnostics, policy text or report bodies. Hashes minimize disclosure; they are not anonymization or authentication. Only configured audit readers may retrieve entries. audit_seconds controls a read-visibility window; expired entries remain unchanged in memory until this local store is destroyed. artifact_seconds independently controls required evidence availability. Both are required trusted configuration, not invented organization retention policy.

The test suite uses an explicit local registry that issues only its own observed producer records. It demonstrates unissued/forged producer refusal, approval revocation after green, cross-tenant and reader/consumer role denial, secret-sentinel exclusion from serialized audit, artifact expiry/removal, rollback-time refusal, bounded-capacity refusal, and reentrant removal/publication withdrawal. These fixture mappings do not qualify production tenant/issuer identity. Task4.4 remains unchecked pending independent review and its external authenticated profile requirements.
