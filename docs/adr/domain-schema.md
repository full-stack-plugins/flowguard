# ADR: workflow domain v1, independent of engine wire objects

`flowguard.workflow/v1` covers the current local StageRecord, BaselineRef and FrozenObligations representations. JSON Schemas live under `schemas/workflow/` with positive/negative fixtures under `fixtures/schema/`. The native ten-path layout is independently versioned `flowguard.docs/v1`. OpenSpec task references support the numeric task-ID subset observed in this repository's approved OpenSpec 1.14.1 plan; no general upstream parser compatibility is claimed.

Canonical digest encoding is **typed Serde JSON v1**, not RFC 8785/JCS: UTF-8, compact separators, fields in Rust declaration order, BTreeMap keys and BTreeSet values in Rust ordering, no floating point. Source digests hash raw file bytes. Frozen payload digest hashes all declared payload fields except its own digest. JSON object input order is not significant after typed parsing. Unknown fields, duplicate object keys and unsupported frozen versions reject; graph/baseline constructors additionally validate version and identities. Typed set constructors normalize repeated set members; JSON Schemas require unique array entries. Consumers must use validating constructors, not assume plain deserialization authenticates an object. Structural digest consistency never proves source authority.

Stable graph ownership is (owner,stage), with one node per pair. Project stages 02/07/10 require owner `project`; feature stages require a non-project owner. Dependencies are explicit, do not implicitly inherit node acceptance, and reject dangling/cyclic references. Source-path discovery is separate from graph records; the controller supplies that association. Graph ordering is deterministic, limited, and independent of input order.

BaselineRef requires exact repository, stage 02/07, immutable hexadecimal revision, content/policy digest, approval reference and requirement set. `resolve_baseline` creates a separate structural snapshot per requirement; it does not authenticate the approval or resolve revision existence. ReleaseRef compares the exact nonempty feature→09-digest map. Real baseline authenticity remains the provider's responsibility.

The subsequent gate slice adds strict `flowguard.gate/v1alpha1` GateDecision and `flowguard.gate-mapping/v1alpha1`, paired with actual GE reports; see `gate-contract.md`. StageRecord is currently the graph node contract, not a complete accepted-stage artifact containing all evidence links. Task 1.2 therefore remains **partial**, not completed by the presence of these schemas.

Shared `RunBinding` is imported from GuardEngine without local field additions. GitGuard candidate digests use unprefixed hexadecimal SHA-256; the adapter adds the required `sha256:` URI-style algorithm prefix. Candidate/base objects and snapshot bytes are actually verified through GitGuard, but local repo/controller identity remains advisory. Dirty snapshots are rejected rather than pretending a commit digest covers dirty bytes. Neither engine protocol is extended.

Dependencies use local sibling source paths and exact crate version 0.1.0 for development only. These are not independently distributed immutable release pins. Source module hashes and available commits are recorded in the slice report; release compatibility remains pending GE-RELEASE.

## Accepted-stage audit profile (task 1.2)

`flowguard.accepted-stage/v1alpha1`, kind `StageRecord`, profile `local-controller-observed` is a separate evidence-bearing artifact, implemented as `AcceptedStageSnapshot`. It preserves the original `flowguard.workflow/v1` graph node and schema unchanged. The earlier partial note describes the old node-only slice; this new local audit profile fills that artifact gap, subject to independent review. Schema: `schemas/workflow/accepted-stage.json`; native envelope and binding reference the actual GuardEngine schema rather than extending it.

`QualifiedStage::export_snapshot(current_plan, graph, binding, frozen, provider, now)` first bounds all borrowed inputs, then checks exact graph/context/frozen/work associations and invokes the existing complete `consume`, including recursive current producer/approval checks for dependencies. Only Accept receipts export this profile; skipped/inherited receipts cannot be relabeled accepted. No qualification predicate changes. The controller remains responsible for trusted current plan, provider and clock. An optional fixture-only provider is not host identity authentication.

The payload records the complete selected graph node and graph, immutable plan/work/graph/context references, original native binding plus full candidate scope digest, complete FrozenObligations including baseline digest, frozen required scopes, exact dependency-stage→plan references, original native gate envelope and its digest, GateDecision/artifact references, stage approval reference/action/purpose and observed time. The plan digest is a reference to the protected plan, not a deserializable authorization policy. Baseline provenance comes from FrozenObligations: this profile cannot fabricate an authenticated BaselineRef that the accepted plan never held. Native upstream verdicts are retained unchanged. No external evidence bytes are fetched by loading this artifact.

The outer digest hashes typed compact Serde JSON of `(api_version, kind, profile, payload)` using the existing `sha256:` encoding. Struct fields use declaration order; maps use lexical Rust ordering; embedded frozen JSON uses serde_json's sorted map order. Ten repeated real exports and semantic JSON object-key reordering must encode identically. This is not JCS. Source/report digests retain their native byte meanings.

`AcceptedStageSnapshot::from_json` has a 1MiB raw-input limit and a recursive duplicate-key pass before typed/set normalization. It rejects unknown fields/version/profile, malformed/empty identities, changed digest, incorrect graph/context/action/frozen/required/artifact linkage, and non-completed/non-complete envelopes through existing native validators. Export has a 512KiB combined borrowed encoding budget before cloning or hashing input structures; load's typed payload is bounded to 768KiB, 64 graph nodes/dependencies and 256 required scopes. These are local bounded parsing limits, not a latency guarantee.

The result of loading is **historical structural audit data only**. It neither authenticates bytes nor proves current approval; a fully forged/rehashed artifact is not a trust source. A valid historical artifact remains structurally readable after revocation, while another export fails current `consume`. Neither snapshot nor QualifiedStage has Deserialize; no snapshot→QualifiedStage conversion exists (compile-fail tests). The literal observed state `accepted` carries no live authority. Production approval/provider and immutable-source authority limitations remain unchanged.
