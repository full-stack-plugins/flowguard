# Linux local durable workflow attempts

Status: implemented for independent review; tasks 4.1/4.2 acceptance belongs to root. This supplements the memory profile, with no production FG-GATE or execution authority.

`DurableRunStore` is opt-in: create an explicitly chosen empty owner-private directory, or open an existing initialized store. A normal gate check still makes no persistent writes. The Linux descriptor/lock/replace protocol is adapted from independently reviewed GitGuard df2f756; it does not consume GitGuard's domain-specific ReuseKey or private Consumption. Each event replays the existing FlowGuard MemoryRunStore logic rather than another CAS implementation. The extracted work-level methods are crate-private; public registrations still require an actual PendingGate.

Storage protocol: final directory open uses O_DIRECTORY/O_NOFOLLOW; owner/private mode and local filesystem allowlist checked. Files anchor to the open directory via /proc/self/fd, use O_NOFOLLOW/O_NONBLOCK, and must be regular, owner-private, singly linked. `run.lock` contains a store identity and uses nonblocking flock across participating processes. Under the lock: load/verify checksum/replay strict events -> apply transition -> write same-directory temporary -> file fsync -> atomic rename -> directory fsync. Contention rejects with retry wording. At/after publication, errors say outcome uncertain. Reopen and inspect `generation`, `current` and original idempotent reservation before retrying. Generation observations remain subject to a subsequent CAS race; they are not claims of ownership or authorization.

Wire format: `flowguard.attempt-log/v1alpha2`, `schemas/workflow/attempt.json`, closed snapshot {api_version,store_id,events,checksum}; closed tagged Advance/Reserve/Append/Publish events. Checksum is SHA256 of serde compact JSON tuple [api_version,store_id,events]. Work identity holds validated native GE binding/required coverage plus the full work digest computed by PendingGate. Exact target/work digests remain opaque recorded controller identities; checksum is corruption detection, not identity authentication. Replay rejects bad versions/unknown fields/invalid GE binding/invalid transitions. Missing state or corrupt storage never resets to an empty history. `Append.work_digest` is taken from the original GateRun private field and checked against its reservation on every replay. Public append accepts only GateRun; callers cannot rebind envelope bytes by supplying a digest. `Append.envelope` retains the original GateRun canonical UTF8 JSON bytes as a string and is validated by the actual GE loader on replay; no normalized replacement of original evidence is made.

Limits: 16MiB snapshot, 10,000 events, 3MiB encoded input mutation; inherited memory caps of 1024 targets/reservations, 1MiB/envelope and 32MiB aggregate original envelope bytes (the snapshot cap may be reached earlier). Capacity rejects without pruning. Repeated idempotent calls can append redundant logical events until the finite event limit, while history/published original bytes stay unchanged. Temporary leftovers are ignored and not automatically deleted.

Supported profile: cooperative processes of the same trusted controller user, immutable/controlled directory ancestry, local persistent storage. ext-family/XFS/Btrfs/overlayfs allowlisted; only workspace overlayfs tested. The operator must ensure overlay backing is persistent and honors fsync. tmpfs, network/unknown filesystem types reject. Unsupported: malicious same-UID mutation, lock deletion or cloning, restored older snapshots, authenticated tenants, network coordination, hardware power-loss qualification. File ownership is not production producer authentication.

Tests: real Git A/head1 versus different A/head2, independent B in the same worktree; head1 ALLOW late after head2 BLOCK remains only history across reopens. Actual subprocesses race one generation CAS; process exits after temporary fsync before rename and after rename before directory fsync preserve whole old/new state, release locks and permit continued CAS. These unit fault tests exercise storage events over a captured GE binding; they are not hardware fault tests. Separate integration tests run actual prepared gates and real Git candidate binding. No repository writes are performed by the store itself; fixture setup commits test candidates.

Unchanged boundaries: archived envelope structure/binding is not verified artifact retention or current authority. Consumers must run real GE/FlowGuard evidence and fresh authority validation. This is not an execution-intent/receipt state machine, does not coordinate remote writes, and does not atomically retain separate audit logs or report artifact blobs. `fixtures/schema/attempt-valid.json` is captured from an actual temporary Git/gate cancellation/reopen scenario; its temporary Git repo is not retained and it is a storage wire fixture only.

Version change: v1alpha1 lacked original completion work identity and could mislabel an old result under a new authority policy with otherwise equal binding/scopes. v1alpha2 requires the original private full-work digest in Append. Old logs reject; no silent migration or caller-provided digest repair is offered. Recompute under the intended exact policy in a new store if old history cannot be trusted. GateRun is not deserializable and its original digest has no public setter/constructor. Local on-disk checksums still do not authenticate hostile owner edits.
