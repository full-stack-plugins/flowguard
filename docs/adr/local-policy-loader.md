# Controller-pinned local policy profile

Status: implemented local profile; independent review pending. Supports portions of tasks 2.5/3.1, not their full acceptance.

`policy::load_and_freeze` reads one JSON document through `AllowedRoot`, compares SHA-256 of the exact raw bytes to an independently supplied controller pin, checks exact context/baseline/graph digests, and invokes the existing `obligations::freeze`. `PolicySnapshot` exposes only its raw digest and immutable frozen obligations. Missing stages/providers remain missing; no report is collected before freezing. No engine DTO is duplicated.

Wire schema is a closed object with required fields: `version` exactly `flowguard.policy/v1alpha1`, `context_digest`, `baseline_digest`, `graph_digest`, and `obligations` (existing closed EvidenceObligation objects). Unknown/duplicate object keys, unknown versions, duplicate obligations, empty identities, invalid digests and existing obligation budget violations reject. Policy document is limited to 1 MiB; root reads are separately capped by AllowedRoot at at most 16 MiB. Graph digest is SHA-256 over existing deterministic serde JSON StageGraph encoding. Pin binds raw file bytes, including whitespace; frozen digest continues to bind canonical semantic obligations. Do not infer that equal frozen digests mean identical policy file bytes.

Trust boundary: the controller must choose an authorized immutable configuration root, supply the pin independently of candidate documents, and supply the expected current context/baseline/graph. A caller who controls both file and pin can replace the policy. Neither filesystem path nor matching hash authenticates an actor. This is not a production protected-config provider. The loader is read-only and never discovers a policy automatically from a candidate or writes `.flowguard/`. It inherits AllowedRoot's requirement that the controller prevent concurrent filesystem mutation; no hostile-directory race protection is claimed.

Call sequence: validate actual GG candidate -> derive full FlowGuard context digest -> choose exact graph and baseline -> controller supplies expected policy pin -> load_and_freeze -> pass returned frozen obligations to prepare_gate. Existing raw freeze remains available for explicit fixtures and lower-level integrations. The gate's upstream GE EligibilityPolicy map is still separately controller-supplied; this slice does not authenticate or load that map, stage approval declarations, baseline authority, or action applicability. Caller must retain `raw_digest` in its audit record if exact policy file identity is needed.

Tests use real temporary files, existing graph/freeze code and deliberately local pins. Tests prove byte integrity and binding checks, not host authority. Local expected errors are redacted static strings; no policy contents or filesystem paths are returned.
