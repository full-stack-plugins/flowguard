# Process-local append and generation CAS

Implemented local profile of tasks 4.1/4.2, independent review pending. `MemoryRunStore` is explicitly constructed by the controller; gate checks alone create no store and write no source files. No dependency on GitGuard persistence. Dropping the store discards all history; restart, crash durability, authorized disk directories, stored schema, multiprocess transactions and retention are not implemented or claimed.

A private work identity is derived from a real prepared FlowGuard gate. Its target is repo/task/worktree/requirementIds/action. Its full work digest also binds actual GE RunBinding, full GG domain identity, frozen obligation/graph/baseline digest, frozen required scopes, action, exact specialist EligibilityPolicy maps including approved principals, mapping version and FlowGuard analyzer version. No caller-supplied work digest or second engine binding schema is accepted. Serialization is deterministic for the existing closed structs and BTree collections. Store metadata is not a public persisted format.

Controller sequence: prepare -> advance(expected_generation) -> reserve(idempotency_key, generation) -> evaluate/cancel -> append(original envelope bytes) -> publish(run_id, expected_generation). Advance is a mutex-atomic compare-and-swap, increments monotonically and clears the current pointer. Same-target/idempotency repeats return the original attempt only for equal work digest and generation; retries use new idempotency key and runId. A new key cannot reuse an existing runId. Idempotent lookup can return a historical attempt after advancement; it does not republish it. Caller must use returned runId rather than execute a deduplicated proposed attempt.

Append uses the actual GE strict envelope loader, checks reserved run ID, GE binding, required scopes and exact FlowGuard producer, and preserves original bytes. Equal bytes are idempotent; any changed bytes (even whitespace) conflict. Publication is single-assignment within a generation, checks both full work identity and expected generation, and requires an appended terminal envelope. Replacing a prior publication requires a new generation. Late results remain history and cannot roll back current state. History returns detached bytes in run-ID order, not time order. Queries for obsolete full work identities return no current result.

Storage is not eligibility: error/cancelled/BLOCK envelopes may be the current diagnostic result. Append performs structural validation only, does not fetch artifacts or authenticate producers, and does not grant execution. Consumers must still use GE/FlowGuard artifact and fresh authority evaluation. The store is a trusted controller's process-local object; it has no tenant authenticator or network access. Targets separate supplied repo/task/requirements but do not authenticate those names.

Budgets: at most 1024 targets and 1024 reservations, 128 bytes per nonblank idempotency key, at most 1 MiB per envelope (GE can impose tighter budgets), 32 MiB aggregate envelope bytes. No eviction hides history; exhaustion fails closed. Poisoned mutex fails closed. Thread tests cover racing advancement/publication; no cross-process claim.
