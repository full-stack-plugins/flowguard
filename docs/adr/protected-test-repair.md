# Local protected test repair

`ProtectedRepairPlan` extends the existing `ActionPolicy`/`assess` classification without changing the public policy fields. Legacy `assess` remains descriptive: Read/Clarify are read-only, Deliver always requires the delivery gate, Skip always requires protected skip qualification, and WriteTests requires current approval when enabled. Both APIs share the action classification. Empty/oversized stage sets reject test-repair assessment rather than treating no requirements as approval. Legacy descriptive enums are not concrete path authorization or executor capabilities.

Freeze `RepairContext` (protected stage plan, exact validated candidate binding, FrozenObligations and current ActionPolicy) with explicit test-file paths and trusted controller time. Required stages must exactly equal the frozen obligation stage set, the protected stage graph/context and actual native contract coverage anchors must match. Original domain obligations, baseline digest and full GG candidate scope remain bound; unavailable TestGuard evidence is not removed. Borrowed metadata is counted before hashing/cloning. The full repair descriptor hash includes the stage plan, exact context/frozen digest, stage set, enabled flag, allowed test paths, time and original native GE policy.

The actual existing GE contract/binding are reused; no synthetic contract or fake REQUIRE_APPROVAL envelope is constructed. A dedicated `workflow.write-tests` approval purpose and `write-tests:<digest>` action replace the delivery-stage action. Its approver allowlist comes from the protected stage-accept plan. Native AuthorityProvider must authenticate approval records; GE `validate_approval_record` checks purpose/action/full binding/contract/principal and current validity. Local fixture records exercise this port; they do not authenticate a real hosting service or production issuer.

`authorize` accepts only WriteTests and a nonempty subset of exact allowed paths. Initial scope is explicitly `tests/` paths ending .rs/.py/.ts/.js/.java, portable ASCII components, no traversal, wildcard, backslash or .git component. This is a bounded controller-selected test-source profile, not proof that arbitrary file contents are harmless. No file creation, edit, command or sandbox execution occurs. The controller must separately enforce these paths in any execution system.

The non-deserializable `RepairReceipt` borrows the protected plan, paths and opaque approval reference. Every refresh receives the current ProtectedRepairPlan and current RepairContext, compares exact plan/context/applicability, checks path containment and time, and queries approval authority again. A changed allowed set, stage set, candidate, frozen obligations, enabled flag or plan cannot reuse an old receipt. Successful refresh records a nondecreasing last observed controller timestamp; trusted wall-clock correctness is still the controller's responsibility. No cached approval outcome is reused.

Budgets: 64 required stages of at most 256 bytes; 64 explicit paths of at most 1024 bytes; context (policy stages + original native GE policy + FrozenObligations) at most 64 KiB serialized; selected path set at most 64 KiB serialized; approval reference <=256 bytes and control-free. Existing ValidatedBinding admission applies before domain hashing. Source paths and counts are checked before serialization. The bounded combined inputs keep descriptor hashing/cloning finite; no deadline or full OS isolation is claimed.

TDD tests demonstrate real missing TestGuard → existing FG/GE BLOCK while a separately approved, exact repair scope remains usable. The blocked gate and FrozenObligations bytes remain unchanged, and old legacy delivery/skip assessments are preserved. Approval substitution/revocation/expiry, changed current repair plan and candidate applicability, invalid paths, backwards clock and budget failures reject. This is not delivery qualification, stage acceptance/skip, an approval issuer or a production write provider.
