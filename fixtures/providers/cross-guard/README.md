# Actual cross-Guard fixture

This fixture executes the actual pinned AG-EVIDENCE, CG-ADAPTER, TG-EVIDENCE and GG-CANDIDATE paths on the same committed repository. `actual/source.bundle` reconstructs candidate `e6ec0e97fb3a87e06b4d95a4a9ea6a6c4afdba3d`. `actual/PROVENANCE.json` records exact source/tool pins, commands, exits, original artifact hashes and the hashes of controller inputs frozen before results. `actual/capture-sources/` preserves the exact generator source bytes used at capture time; the formatted example has identical behavior.

| Producer | Actual scope | Verification and limits |
| --- | --- | --- |
| ArchGuard `7f21806f` | Cargo declarations from immutable candidate; enforced core→app prohibition | Native GitEvidenceBundle verify/load; not runtime or language-wide coverage |
| CodeGuard projection `72d80ae4`, native `f5661d51`, Ruff 0.16.8 | Qualified F401 only, exact app.py/config/tool digests | Original native stdout/schema/command flags preserved; native aggregate exit **3** remains 3, projection exit 0; standalone controller binding, not production host authentication |
| TestGuard `e2e91471` | Actual offline Cargo 1.99 discovery and execution of one trusted local test | Native parse, engine projection and verify_bundle; fixture baseline, not SG approval or arbitrary candidate-code sandbox |
| GitGuard `ff1afb31` | Actual candidate, allowed path scope, clean tree, submodule scope | CandidateSnapshot validation and actual BoundCheck; no remote writes |

AG/GG/TG use GE `20c53cdb`; the preserved CG executable uses GE `c80ec325`. Exact full pins and executable hashes are in provenance. Two distinct protected AG/GG candidates retain their own domain policy digests. Source digests remain scoped to the original producers. The workflow baseline is the committed fixture baseline, explicitly local and unauthenticated.

The test issuer admits only recorded envelope digests under `fixture-ci`. This demonstrates local contract interoperability, not production identity, runtime completeness, promotion eligibility, or write permission. Actual four-way consumption is ALLOW only under this explicit fixture authority. Each missing producer gives Partial/BLOCK. Wrong candidate/baseline/source, changed artifacts, unqualified versions, the actual CG preparation error, unavailable or revoked identity cannot produce ALLOW.

## Reproduction

Use source-only archives for the pins in provenance and the FG commit containing this fixture. Place sibling GE/GG/AG/SG archives to satisfy existing path dependencies; do not build against moving sibling working trees. Reuse existing Cargo targets, with `CARGO_INCREMENTAL=0`, `--locked --offline` and the installed toolchain.

1. Build FG `--example generate_cross_guard` from that archive.
2. Copy `generate_testguard.rs` into the pinned TG archive as `examples/generate_cross_guard_tg.rs`; build that example in the TG target.
3. The capture script currently names the existing shared target binaries and preserved qualified CG/Ruff binaries under `/workspace`; it checks their hashes before use. Run `python3 fixtures/providers/cross-guard/capture.py OUTPUT NEW_WORK_DIRECTORY` with the toolchain environment loaded. It installs nothing. The work directory must be new. Only the committed, fixed local fixture is executed; it has no external Cargo dependencies or build scripts.
4. Retain all generated bytes and command logs. Native timestamps/run IDs and absolute working paths may change; regenerate the whole set, never patch existing successful producer envelopes to fit a new context.
5. `cargo test --locked --offline --test cross_guard_contract --test scoped_baseline` replays immutable evidence, reconstructs the Git repository, verifies AG/GG candidate correspondence and GE artifacts, and tests policy/identity failures. Default tests need no Ruff execution or downloads.

CG's preparation invocation intentionally fails with no native report before native execution; its frozen required scopes and prepared contract are not an ALLOW claim. The script subsequently invokes the original native command and passes its raw stdout unchanged into the qualified sidecar. The source fixture's `Cargo.lock` is generated offline before commit and is present in the bundle.
